Structural Properties Inspected

  • Numeric IP Host: Raw IP addresses (e.g., 192.168.1.1) used to bypass domain reputation systems.
  • Deceptive Subdomain: Trusted brands placed as subdomains on unrelated domains (e.g., sbi.co.in.attacker.com).
  • Typosquatting Domains: Visual homoglyphs (e.g., paypa1 instead of paypal) detected via edit distance.
  • Embedded '@' Symbol: Under RFC 3986, text before @ represents user credentials; browsers route only to the host after @.
  • URL Shorteners: Services like bit.ly that conceal the destination link.

Why Offline Inspection?

Navigating to an untrusted link exposes the system to browser exploitation, server IP tracking, and telemetry triggers.

Offline structural inspection safely evaluates link syntax using standard RFC specifications without alerting the threat actor.

Safety Tip

Never click links in unexpected text messages or emails. Type the official URL directly into your browser address bar.

Android Permission Risk Guidance

Review sensitive Android capabilities requested by an application to evaluate privacy exposure and receive explainable Allow, Deny, or Review guidance.

Permissions alone do not establish that an application is malicious. Consider the app's functionality, developer and source before making a decision.

Privilege risk must always be assessed in context: navigation apps legitimately need GPS, but offline utility apps requesting SMS or Accessibility access indicate high threat likelihood.

Permission Privilege Model

Android enforces application sandboxing. Permissions define capabilities an application may exercise to access hardware or personal data.

  • Special Access: Privileges such as Accessibility Services and System Overlays that can bypass the sandboxing of other applications.
  • Sensitive Access: Runtime permissions (SMS, Contacts, Location) requiring explicit user consent.
  • Standard Access: Low-risk capabilities (Coarse Location) with limited privacy exposure.

Recommendation Tiers

  • DENY: Extreme abuse risk (e.g. Accessibility trojans or SMS interception). Reject unless fundamentally required.
  • REVIEW: Context-dependent (e.g. Camera or Contacts). Allow only if core app function requires it.
  • ALLOW: Safe to grant for apps requiring basic regional context.

Context is Key

A navigation app legitimately requires precise GPS. However, an offline calculator or flashlight requesting SMS or Accessibility is almost certainly malicious.
